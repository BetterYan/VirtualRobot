# 仿真器与算法端架构（SLAM 验证阶段）

> 状态：**当前生效**。本架构取代"一期一体式"作为主工作模式（一期场景保留可运行）。
> 核心转向：Godot 退化为**无图虚拟传感器仿真器**，Python 端承担**全部定位算法**，从 2D SLAM 开始验证。

## 1. 背景与转向

- 一期（Godot 一体式覆盖清扫）已跑通，但 `core/world_model.gd` 直接读取了真实房间信息——**机器人"开了天眼"**，无法验证真实的定位算法。
- 参照《03-机器人定位算法调研.html》方案 A（2D 激光 SLAM）路线，本项目进入 **SLAM 验证阶段**：
  - Godot 构建物理世界（墙体/家具/机器人/传感器），但**不向算法端提供任何地图与真实位姿**（无图模式）
  - Python 端只接收带噪声的传感器流（里程计 + 2D 激光），**自行建图与定位**
  - 真值数据走独立评估通道，仅用于打分，绝不进入算法

## 2. 职责划分

```
┌──────────────────────────┐   WebSocket(JSON)    ┌────────────────────────────┐
│  Godot = 虚拟物理世界      │ ──── sensor_frame ──▶ │  Python = 算法端 (vrobot)   │
│  · 场景/物理碰撞           │  里程计(带噪)+激光     │  · 2D SLAM：建图+定位        │
│  · 传感器仿真（雷达/里程计）│ ◀──── cmd_vel ──────  │  · 运动控制（自动探索/遥控）  │
│  · 键盘遥控（采集数据）     │  （可选自动模式）      │  · 实时地图可视化            │
│  · 轨迹/渲染              │ ─── ground_truth ───▶ │  · 真值对比评估（不进算法）   │
└──────────────────────────┘   仅评估用，可选        └────────────────────────────┘
```

| 原则 | 说明 |
|------|------|
| **无图** | 算法端唯一输入是传感器流；Godot 不发房间栅格、不发家具、不发真值位姿到算法通道 |
| **真值隔离** | `ground_truth` 消息独立通道，SLAM 模块在代码层面禁止 import；只有 evaluator 使用 |
| **契约先行** | 消息格式只定义在 `protocols/message-schema.md`，两端各自实现，改动必须先改文档 |
| **算法可离线** | SLAM 核心是纯 numpy 函数式模块，不依赖网络/可视化，可用录制数据或合成数据离线测试 |

## 4. 关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | **Python 为 WebSocket 服务端，Godot 为客户端** | 算法端常驻（服务器/可视化）；Godot 场景可随时重启重连，调试不中断算法端 |
| D2 | **v1 算法 = TinySLAM 式**（里程计预测 + 扫描匹配修正 + 对数概率建图），RBPF 粒子滤波列为 v2 | 相关性扫描匹配无需梯度/特征，实现简单、鲁棒，是理解 SLAM 的最佳入门路径；接口上预留粒子滤波替换位 |
| D3 | **坐标系**：沿用 Godot 像素坐标（x 右、y 下、θ 绕原点顺时针为正即 Godot rotation 语义），两端公式一致 `p' = p + v·(cosθ, sinθ)` | 避免坐标翻转错误；SLAM 对 y 轴方向不敏感，栅格地图跟着一致即可 |
| D4 | **栅格分辨率独立于 Godot TileMap**（默认 8px/格，可配） | 算法分辨率是 SLAM 参数，不是渲染参数 |
| D5 | **一期 core/ 算法保留不删** | 作为"开天眼"对照基线，也保留覆盖规划成果，后续 Planning 模块移植回来 |

## 5. 数据流与频率

- Godot 物理帧 60Hz → 传感器打包 **20Hz**（每 3 物理帧）上行 `sensor_frame`
- Python SLAM 每帧处理 ≤5ms（72 射线、140×80 栅格量级），20Hz 实时无压力
- Python 每 SLAM 帧回传 `cmd_vel`（自动模式）；Godot 指令超时 0.5s 未收到则停车（安全兜底）
- 真值 `ground_truth` 与 `sensor_frame` 同频上行，evaluator 单独消费

## 6. SLAM v1 算法管线（slam2d.py）

```
sensor_frame 到达
   │
   ├─ 1. 里程计预测：δ = odom(kt) ⊖ odom(k)  →  pose_pred = pose ⊕ δ
   ├─ 2. 扫描匹配：在 pose_pred 附近窗口 (±dx,±dy,±dθ) 内
   │      相关性搜索，得分 = Σ map.prob(扫描命中点)，粗→细两级
   ├─ 3. 位姿更新：pose = argmax(score)（未命中质量阈值则保持预测位姿）
   └─ 4. 建图：Bresenham 对每个命中射线做 log-odds 更新（命中+lo，途经-lo）
```

v2（预留）：RBPF 粒子滤波（particle.py）——每个粒子持独立地图，解决长航时里程计漂移与回环。

## 7. 扩展规划

### Godot 场景扩展（仿真世界不变式）
新增场景只需实现 `sim/` 下的同一组节点（雷达/里程计/机器人），走廊、多房间、动态行人只改场景不改协议。
- sim3d：3D 场景虚拟 2D 切片雷达（低垂面射线），协议不变即可复用算法
- 动态障碍：走动的 NPC，验证动态物过滤

### 算法扩展（slam/ 包不变式）
每个算法是一个纯类：`feed(odom, scan) -> result`，互不感知通信与可视化。
- v2：RBPF 粒子滤波（Gmapping 思路）
- v3：图优化后端 + 回环（对应调研报告 LIO-SAM 思路的 2D 版）
- 3D：新增 `slam3d/`（KITTI 式点云配准）；`sensors/` 加 3D 点云消息
- VSLAM：新增 `vslam/`（特征提取/跟踪，OpenCV），Godot 侧加相机传感器消息

## 8. 当前验证结果（2026-09-29）

合成世界端到端测试（`projects/brain/tests/`，15 项全部通过）：

| 指标 | 数值 | 说明 |
|------|------|------|
| 终点位姿误差 | **2.4 px / 0.4°** | 纯里程计对照：13.7 px，提升 5.7 倍 |
| 墙面召回率 | **100%** | ±3 格容差（v1 无回环，允许全局漂移偏移） |
| 误报率 | **0%** | 可及区域内假墙比例 |
| 轨迹连续性 | 单步 < 30px | 无匹配发散 |
| 通信链路 | ✓ | 模拟客户端 → SimServer → SLAM → cmd_vel 回流 |

结果图：`docs/slam2d-验证结果.png`

实现过程中沉淀的三个关键经验：
1. **未知格 ≠ 墙**：占据判定须用严格大于阈值（log-odds=0 的未观测格曾把全部未知区判成墙，误报率 78%）
2. **双线性插值是精度关键**：最近邻概率查询存在格内量化平台，累积漂移反而超过纯里程计；改双线性后终点误差从 30px 降到 2.4px
3. **仿真数据要避免退化路径**：路点贴墙会触发"卡死 + 里程计狂奔"，测试需带卡死保护

## 9. 运行方式

Python 端使用 **uv** 管理依赖（`pyproject.toml` + `uv.lock`，PEP 735 依赖组）：

```bash
# 1. 启动算法端（先启动）
cd projects/brain
uv sync                                             # 首次：创建 .venv 并按锁文件安装
uv run python -m vrobot.apps.slam_node --config configs/slam2d.yaml

# 2. 启动 Godot 仿真器
#    Godot 4.7 打开 projects/godot → F5（主场景 sim2d.tscn）
#    HUD 显示 WS 已连接后：方向键/WASD 遥控，或点 Auto 让算法端驾驶

# 3. 离线算法验证（无 Godot）
cd projects/brain && uv run pytest tests/ -v
```
