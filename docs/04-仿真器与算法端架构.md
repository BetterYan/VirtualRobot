# 仿真器与算法端架构（SLAM 验证阶段）

> 状态：**当前生效**。本架构取代"一期一体式"作为主工作模式（一期场景保留可运行）。
> 核心转向：Godot 退化为**无图虚拟传感器仿真器**，Python 端承担**全部定位算法**，从 2D SLAM 开始验证。

## 1. 背景与转向

- 一期（Godot 一体式覆盖清扫）已跑通，但 `core/world_model.gd` 直接读取了真实房间信息——**机器人"开了天眼"**，无法验证真实的定位算法。
- 参照《03-机器人定位算法调研.html》方案 A（2D 激光 SLAM）路线，本项目进入 **SLAM 验证阶段**：
  - Godot 构建物理世界（墙体/家具/机器人/传感器），但**不向算法端提供任何地图与真实位姿**（无图模式）
  - Python 端只接收带噪声的传感器流（里程计 + 2D 激光），**自行建图与定位**
  - 真值数据走独立评估通道，仅用于打分，绝不进入算法

## 2. 职责划分

```
┌──────────────────────────┐   WebSocket(JSON)    ┌────────────────────────────┐
│  Godot = 虚拟物理世界      │ ──── sensor_frame ──▶ │  Python = 算法端 (vrobot)   │
│  · 场景/物理碰撞           │  里程计(带噪)+激光     │  · 2D SLAM：建图+定位        │
│  · 传感器仿真（雷达/里程计）│ ◀──── cmd_vel ──────  │  · 运动控制（自动探索/遥控）  │
│  · 键盘遥控（采集数据）     │  （可选自动模式）      │  · 实时地图可视化            │
│  · 轨迹/渲染              │ ─── ground_truth ───▶ │  · 真值对比评估（不进算法）   │
└──────────────────────────┘   仅评估用，可选        └────────────────────────────┘
```

| 原则 | 说明 |
|------|------|
| **无图** | 算法端唯一输入是传感器流；Godot 不发房间栅格、不发家具、不发真值位姿到算法通道 |
| **真值隔离** | `ground_truth` 消息独立通道，SLAM 模块在代码层面禁止 import；只有 evaluator 使用 |
| **契约先行** | 消息格式只定义在 `protocols/message-schema.md`，两端各自实现，改动必须先改文档 |
| **算法可离线** | SLAM 核心是纯 numpy 函数式模块，不依赖网络/可视化，可用录制数据或合成数据离线测试 |

## 4. 关键设计决策

| # | 决策 | 理由 |
|---|------|------|
| D1 | **Python 为 WebSocket 服务端，Godot 为客户端** | 算法端常驻（服务器/可视化）；Godot 场景可随时重启重连，调试不中断算法端 |
| D2 | **v1 算法 = TinySLAM 式**（里程计预测 + 扫描匹配修正 + 对数概率建图），RBPF 粒子滤波列为 v2 | 相关性扫描匹配无需梯度/特征，实现简单、鲁棒，是理解 SLAM 的最佳入门路径；接口上预留粒子滤波替换位 |
| D3 | **坐标系**：沿用 Godot 像素坐标（x 右、y 下、θ 绕原点顺时针为正即 Godot rotation 语义），两端公式一致 `p' = p + v·(cosθ, sinθ)` | 避免坐标翻转错误；SLAM 对 y 轴方向不敏感，栅格地图跟着一致即可 |
| D4 | **栅格分辨率独立于 Godot TileMap**（默认 8px/格，可配） | 算法分辨率是 SLAM 参数，不是渲染参数 |
| D5 | **一期 core/ 算法保留不删** | 作为"开天眼"对照基线，也保留覆盖规划成果，后续 Planning 模块移植回来 |

## 5. 数据流与频率

- Godot 物理帧 60Hz → 传感器打包 **20Hz**（每 3 物理帧）上行 `sensor_frame`
- Python SLAM 每帧处理 ≤5ms（72 射线、140×80 栅格量级），20Hz 实时无压力
- Python 每 SLAM 帧回传 `cmd_vel`（自动模式）；Godot 指令超时 0.5s 未收到则停车（安全兜底）
- 真值 `ground_truth` 与 `sensor_frame` 同频上行，evaluator 单独消费

## 6. SLAM v1 算法管线（slam2d.py）

```
sensor_frame 到达
   │
   ├─ 1. 里程计预测：δ = odom(kt) ⊖ odom(k)  →  pose_pred = pose ⊕ δ
   ├─ 2. 扫描匹配：在 pose_pred 附近窗口 (±dx,±dy,±dθ) 内
   │      相关性搜索，得分 = Σ map.prob(扫描命中点)，粗→细两级
   ├─ 3. 位姿更新：pose = argmax(score)（未命中质量阈值则保持预测位姿）
   └─ 4. 建图：Bresenham 对每个命中射线做 log-odds 更新（命中+lo，途经-lo）
```

v2（预留）：RBPF 粒子滤波（particle.py）——每个粒子持独立地图，解决长航时里程计漂移与回环。

## 7. 扩展规划

### Godot 场景扩展（仿真世界不变式）
新增场景只需实现 `sim/` 下的同一组节点（雷达/里程计/机器人），走廊、多房间、动态行人只改场景不改协议。
- sim3d：3D 场景虚拟 2D 切片雷达（低垂面射线），协议不变即可复用算法
- 动态障碍：走动的 NPC，验证动态物过滤

### 算法扩展（slam/ 包不变式）
每个算法是一个纯类：`feed(odom, scan) -> result`，互不感知通信与可视化。
- v2：RBPF 粒子滤波（Gmapping 思路）
- v3：图优化后端 + 回环（对应调研报告 LIO-SAM 思路的 2D 版）
- 3D：新增 `slam3d/`（KITTI 式点云配准）；`sensors/` 加 3D 点云消息
- VSLAM：新增 `vslam/`（特征提取/跟踪，OpenCV），Godot 侧加相机传感器消息

|------|------|------|
| 终点位姿误差 | **2.4 px / 0.4°** | 纯里程计对照：13.7 px，提升 5.7 倍 |
| 墙面召回率 | **100%** | ±3 格容差（v1 无回环，允许全局漂移偏移） |
| 误报率 | **0%** | 可及区域内假墙比例 |
| 轨迹连续性 | 单步 < 30px | 无匹配发散 |
| 通信链路 | ✓ | 模拟客户端 → SimServer → SLAM → cmd_vel 回流 |

结果图：`docs/slam2d-验证结果.png`

实现过程中沉淀的三个关键经验：
1. **未知格 ≠ 墙**：占据判定须用严格大于阈值（log-odds=0 的未观测格曾把全部未知区判成墙，误报率 78%）
2. **双线性插值是精度关键**：最近邻概率查询存在格内量化平台，累积漂移反而超过纯里程计；改双线性后终点误差从 30px 降到 2.4px
3. **仿真数据要避免退化路径**：路点贴墙会触发"卡死 + 里程计狂奔"，测试需带卡死保护

## 10. 建图路径策略（行业实践 vs 本项目）

### 10.1 行业如何建图

建图分**两个阶段**，常被混为一谈的"弓字形"属于第二阶段：

| 阶段 | 地图状态 | 行业做法 | 说明 |
|------|---------|---------|------|
| **① 建图** | 未知 | **人工遥控** | 商用部署最常见：调试人员开一圈，质量最高 |
| | | **Frontier 自主探索** | Yamauchi 1997，学术/工业标准：不断驶向"已知自由区 ∧ 未知区"边界，直到边界消失。ROS 的 `explore_lite` 即此思路 |
| | | 沿墙绕周 / 螺旋 | 扫地机"快速建图"的工程启发式，追求几十秒出粗图 |
| **② 覆盖 / 清扫** | 已知 | **弓字形（boustrophedon）** | 对**已建好的地图**做覆盖路径规划（一期已实现）；地图未知时画弓形无意义——不知道房间边界在哪 |
| **③ 复用** | 已有 | 重定位（AMCL / NDT） | 建图只做一次，日常运行在已有地图上定位 |

**结论**：随机走（reactive 反应式）永远无法保证完整建图；完整地图来自**系统性探索**（frontier）或人工遥控。弓形是建图之后的覆盖策略。

### 10.2 本项目实现：Frontier 自主探索（v1.1）

`control/explorer.py` 的 `FrontierExplorer`，闭环：

```
每帧（20Hz）：
  1. Frontier 检测：unknown ∧ free 的 8 邻域 → 掩码膨胀 1 格后连通聚类
     （膨胀是为了把射线锥间隙切碎的边界碎片连回同一条边界；
      簇大小按原始格数计，≥4 才算有效目标）
  2. 目标承诺：当前目标 frontier 仍存活（质心 ±4 格）→ 继续前往不换目标，
     杜绝"远近目标来回切换"的锯齿震荡；消亡才按 信息量/距离 重新选
  3. A* 导航：planning/path_finder.py，障碍严格膨胀 2 格（走廊距墙 ≥18px，
     机器人半径 14px），未知区代价 ×3，起点周围 3 格 carve 逃逸气泡
  4. 路点跟随：到达半径 14px，航向差比例控制
  5. 安全层：前方 26px 内有障碍 → 原地转向（不前顶）
  6. 停滞保护：卡死（50 帧位移 <6px）/ 区域停滞（250 帧活动半径 <55px）
     → 目标进黑名单，换下一个
  终止条件：无可达 frontier → done（建图完成，输出提示）
```

**配套的 SLAM 关键帧插入**（`Slam2D`，`insert_min_dist=5px / insert_min_angle=0.15rad`）：
位姿变化足够大才把扫描写入栅格。没有这一条，原地旋转时逐帧入图会让墙体
沿角度方向涂抹成"辐条"，把 A* 的可通行区切割成碎片。

合成世界闭环验证（20Hz 仿真，seed=11）：**2038 步（约 102s 仿真时间）完成全屋探索**，
轨迹覆盖 x:62-801 / y:81-623（房间 900×640），墙面召回率 99.4%，误报率 1.5%，
长航时终点位姿误差 10.7px / 0.4°。测试：`tests/test_frontier_exploration.py`。

配置切换（`configs/slam2d.yaml` → `explorer.mode`）：`hybrid`（默认）/ `frontier` / `reactive`（调试）/ `off`。

### 10.4 本项目实现：混合探索——沿边 → 弓形 → Frontier（v1.2）

`control/hybrid_explorer.py` 的 `HybridExplorer`，把行业两阶段建图落实为一个
四状态阶段机（用户定义的流程）：

```
seek_wall ──前方 <70px──→ wall_follow ──轨迹闭环──→ coverage ⇄ frontier → done
 直行找边界                右手沿边探测              弓形覆盖    未知边界收尾
```

| 阶段 | 行为 | 关键参数 |
|------|------|---------|
| `seek_wall` | 直行，直到雷达前方发现边界 | `wall_detect=70px` |
| `wall_follow` | 沿边探测（-90° 波束侧）：**双波束（-60°/-120°）墙线拟合**同时得到垂距 d 与墙-航向偏角 α，PD 控制 `w = -k1·(d-d_target) + k2·α`（α 项兼做航向对齐与微分阻尼，杜绝纯 P 的蛇形摆动），EMA 平滑，\|α\|>0.5rad 视为跨角假值清零；转角判定**自适应** `d_front < 0.85×当前墙垂距`（固定阈值会与目标侧距冲突，见 10.5 踩坑表） | `side_gain=0.03/px, align_gain=3.0/rad, smooth=0.25` |
| `coverage` | 弓形（boustrophedon）：对"确认自由 ∧ 未扫过"区域按行生成车道（行距 4 格 =32px），贪心最近端点排序，A* 逐段导航 + 每 30 帧重规划当前段（地图持续更新，旧路径可能穿过新障碍） | `lane_pitch=4, min_run=4` |
| `frontier` | 委托 `FrontierExplorer`（内部实例，状态保留）驶向未知边界 | 同 10.2 |

**阶段切换的核心是 swept 掩码**：以机器人历史位置为圆心、20 格（160px）为半径
的圆盘并集。"新自由区" = 确认自由 ∧ 未扫过：

- 沿边**闭环判定**：回到沿边起点 40px 内 且 弧长 >500px（防刚起步误判）；
  超时 4500 帧或卡死则强制进入覆盖
- frontier 阶段每 100 帧检查一次：新自由区 ≥60 格 → 重新生成车道交还覆盖
- **frontier 全不可达时强制兜底**：若仍有 ≥30 格未扫自由区，解除 frontier 的
  done 并强制一轮弓形覆盖（最多 2 轮）——否则几十格的剩余碎片既够不着
  阈值又被 A* 判不可达，会过早宣布"建图完成"
- 覆盖空手而归（无可覆盖区域）→ 200 帧冷却，防止 coverage↔frontier 抖动
- 终止：frontier 无可达边界 **且** 无未扫自由区 → `done`

合成世界闭环验证（seed=11，房间 900×640）：**2250 步（≈112s）完成**，阶段演进
`seek_wall → wall_follow → coverage → frontier`，墙面召回率 **100%**，误报率 **0**，
自由空间覆盖率 96.9%，终点位姿误差 4.3px / 0.0°。测试：`tests/test_hybrid_exploration.py`
（含 `_wall_fit` 几何单元测试：平行墙偏角≈0 / 偏航 30° 拟合出 +30°）。

与纯 frontier（2038 步）相比，混合策略步数略多，但轨迹更有序（沿边一圈 +
弓形扫描），建图过程对观察者更可读，且覆盖阶段天然产出"机器人走过全部自由区"
的轨迹——后续接清扫/巡检任务时可直接复用。

### 10.5 踩坑记录（对后来者最有价值的部分）

| 现象 | 根因 | 修复 |
|------|------|------|
| 探索 5 秒就"完成" | 自由判定阈值 -0.85 需穿越 3 次，开局无自由区 → frontier 恒空 | 阈值放宽到 -0.3（观测一次空即算） |
| 机器人原地打转 2700 步 | 每 15 帧强制重规划 + 打分偏向近处小 frontier → 目标来回切换 | 目标承诺制 + 区域停滞检测 |
| 地图呈放射状星爆、A* 无路可走 | 原地旋转逐帧入图，旋转角超雷达角分辨率，墙体涂成辐条 | SLAM 关键帧插入 + 角速度 2.4→1.5 |
