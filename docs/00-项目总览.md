# VirtualRobot 项目总览

> 扫地机器人打扫房间的仿真项目。可视化呈现与行为逻辑分离，支持"一体式"与"独立大脑"两种运行形态。

## 1. 项目定位

- **可视化层**：Godot 4，负责房间场景、机器人实体渲染、物理碰撞、轨迹与覆盖率展示
- **行为逻辑层**：覆盖路径规划（CPP）、导航、避障、电量管理等核心算法，与渲染零耦合
- **演进路线**：第一阶段逻辑层用 GDScript 内嵌于 Godot；第二阶段迁移为 Python 独立进程，经 WebSocket 与 Godot 通信，接口不变

│   ├── 01-godot起步方案.md     # 第一阶段：Godot 一体式实现规划 ★当前
│   ├── 02-python独立大脑方案.md # 第二阶段：Python 进程 + WebSocket（预留）
│   └── decisions/             # 技术决策记录（ADR），后续按需追加
├── projects/                  # ── 子项目集合（每个子项目独立可构建）
│   ├── godot/                 # Godot 4 主项目（可视化 + 第一阶段内嵌逻辑）

## 3. 子项目职责

| 子项目 | 阶段 | 职责 |
|--------|------|------|
| `projects/godot/` | 一期（当前） | 场景、物理、传感器仿真、渲染；内嵌 GDScript 版行为逻辑 |
| `projects/brain-python/` | 二期（预留） | 接管行为逻辑：栅格地图、覆盖规划、A* 导航、状态机 |
| `protocols/` | 贯穿 | WebSocket 消息 schema，两个子项目共同依赖的唯一契约 |

## 4. 演进路线

```
一期：Godot 一体式
  场景搭建 → 传感器仿真 → 弓字形覆盖 → 分区 + A* → 电量/回充 → 轨迹渲染
                                        │
二期：大脑外置                          ▼
  抽离 core/ 算法到 Python ← WebSocket 对接 ← Godot 仅保留表现层
```

关键原则：**一期写逻辑时就保证 `core/` 不依赖任何渲染节点**，二期迁移只换宿主、不改接口。
